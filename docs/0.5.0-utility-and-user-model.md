# 0.5.0 设计草案：效用模型 + 用户模型

**状态**：原型已实现（纯函数 + 只读预览），**尚未接进世界**。2026-11-08。
**范围**：`src/utility.ts`、`src/user-model.ts`、两个 `tools/preview-*.mjs`、对应测试。
**背景**：调研结论见 `deepseek-memory/notes/companion-memory-research-2026-11-08.md`。

---

## 1. 为什么是这两个

- **候选 + 效用模型**：0.4.x 的 `scoreThought()` 是「显著性 + 来源权重 − 惩罚」，阈值 0.55；忙/刚聊完/未回应都是硬闸门，没法权衡，也说不出为什么被拦。
- **用户模型与事件记忆分开**：现在只有 `person` 档案（可能是一大段原文）和事件记忆，缺「他是谁、最近怎么样、我猜他在意什么」这一小层。Honcho / Zep / supermemory 都把「结论层」单列，我们也可以。

两者都遵守同一条约束：**派生物、可重建、可审计，不污染原始记录**。

## 2. 效用模型

### 2.1 公式

```
值     = 显著性 × 来源价值 × (0.7 + 0.3 × 黏人度) × (0.85 + 0.15 × 亲密度)
打扰   = (基础 0.16 + 忙 0.40 + 休息 0.50 + 刚聊 0.28/0.14
          + 刚主动 0.25 + 未回应 0.18×n + 重复 0.50) × 回应率系数
score  = 值 − 打扰
放行   = score ≥ 0.12 且 未回应 < 2 且 不重复 且 不在休息时段
```

- **记忆类由头**（`memory` / `thread` / `promise`）默认绕过“刚聊过”成本（`bypassRecentChat`）：想起来的事值得打断；但“刚主动过 / 未回应 / 重复”仍然计成本。
- **黏人度**（`clinginess`，0–2，默认 **1.3**）：1 = 中性，越大越愿意开口。它只放大“由头值”，**不动打扰成本**——所以更黏不会变成无视忙/刚聊/被忽略。0.5 克制、2 很黏。
- 来源价值：`thread/promise 0.95`、`anniversary/milestone 0.9`、`memory 0.8`、`emotion 0.75`、`body 0.7`、`social 0.6`、`agenda 0.45`、`weather 0.35`。
- 回应率系数 = `1 + (0.5 − replyRate) × 0.5`，夹在 `0.75–1.25`；回复率高 → 打扰更便宜。
- `busy` **只加成本不硬拦**：一个 0.9 的话头仍可能在忙时过线（0.17），但社会的 0.55 不会（−0.25）。宿主要硬拦也可以。
- 每一项都进 `terms`，心理活动日志里能看到「值 0.57 = 由头 0.73 − 打扰 0.16」。

### 2.2 输入/输出

见 `src/utility.ts`：`UtilityInput` / `UtilityResult` / `computeUtility` / `rankCandidates` / `outcomeOf` / `updateReplyRate`。

## 3. 用户模型

### 3.1 数据模型

`src/user-model.ts`：`UserModelItem { key, kind: fact|pattern|hypothesis, text ≤100, confidence, evidenceRefs, source: stated|deduced|induced }`，`UserModel { version, derivedAt, sourceHash, items }`。

### 3.2 推导规则（确定性、无模型调用）

| key | 来源 | 规则 |
| --- | --- | --- |
| `identity` | 人物卡 | 角色 / 关系 / 称呼 / 生日；置信 0.95 |
| `preference` | 人物卡 preferences + 文本 | 拆片段、去重、最多 2 条；置信 0.85 |
| `boundary` | 人物卡 boundaries + 文本 | 拆片段，和偏好重复的丢掉（线上脏数据容错） |
| `routine` | 近 30 天 episode 的本地小时 | 取 3 小时窗，计数 ≥5 且占比 ≥25%；多个窗并列取离圆均值最近的 |
| `focus` | 未完成 thread 或近 7 天高重要度 episode | thread 优先；置信 0.7 / 0.5 |
| `mood` | 近 14 天 `details.userEmotion.label` | 最高标签 ≥3 且占比 ≥30%；排除 musing/legacy/recap |
| `hypothesis` | 近 14 天负面情绪 + `cause` | 同一 cause ≥2 次、总负面 ≥3；置信 0.35–0.55，带证据 |

### 3.3 注入

- `renderUserModel()` 输出：
  ```
  【我对他的理解】
  - 确定：…
  - 习惯：…
  - 近况：…
  - 偏好：…
  - 也许：…
  ```
- 预算：>5 行 / 300 字截断；假设永远最后，前缀「也许」。
- 接进 `memoryDigest()` → `companion.context`（piggyback，不是 system 前缀 → 不会触发前缀重建）。
- 与现在的 `他：${person.text.slice(0,180)}` 二选一（2026-11-08 已定）：**模型有内容时用模型块替代 person 行**，没有则回退 person 行，避免两份画像打架；QQ/生日等硬信息继续走 person/规则。

### 3.4 存储与生命周期（待做）

- 夜间巩固后重算，写 `data/private-companion/model.json`（原子写、`.bak`、`sourceHash` 幂等；同一份输入不重写）。
- `sourceHash` 变了才重算；证据记录全被删除/归档的 item 自动退场。
- 面板加「他对我的理解」页：每条显示 kind/置信/证据数，可删除单条；**删除后不再参与注入**。
- 假设条目不进「确定」区；周反思可以产出新假设，但必须带 `evidenceRefs`。

### 3.5 已知取舍

- 当前线上数据里偏好/边界被写成同一句 → 已容错，边界为空就不显示。
- `routine` 可能把深夜记录当成「他常在凌晨出现」；置信 0.74，不写成断言。
- 情绪标签有 `musing` 污染（她的自省被打了 userEmotion）→ 已排除；后续应在写入端修。

## 4. 风险、回滚

- **默认不改行为**：两个模块都还没被世界引用；接线时用 `proactiveDecision: 'gate'` 默认 + `userModelEnabled: false` 默认。
- **回滚**：删 `model.json` 即回到 person 行；效用模型切回 `gate` 即恢复 0.4.5 行为。
- **成本**：用户模型 154 字 ≈ 80 token/轮，且只在上下文签名变化时推送；效用模型零额外模型调用。
- **数据安全**：只读预览，不写任何线上文件；`MemoryStore` 预览实例不开锁。
